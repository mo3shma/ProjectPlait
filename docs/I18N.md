# Plait in English and Arabic

Plait speaks English (default) and Arabic. It follows the phone's language; Settings, Language (or Android 13+'s per-app
language screen) overrides it. `app.plait.i18n.AppLocale` holds the answer for the whole process: screens, widgets,
notifications, services and workers all use the same language.

## Getting a string
- Compose: `stringResource(R.string.x)`, `stringResource(R.string.x, a, b)`, `pluralStringResource(R.plurals.x, n, n)`.
- Anything else (data layer, generated text, notifications, widgets, exports, AI prompts): `Txt.s(R.string.x, a, b)` and
  `Txt.plural(R.plurals.x, n)` (n is the format argument when no others are given). No Context needed. Never call
  `context.getString` outside Compose: on Android 12 and older it would ignore the in-app choice. A Context that must speak
  the app's language (RemoteViews, a notification builder) comes from `AppLocale.wrap(context)`.
- Unit tests need no setup: `Txt` reads `src/main/res/values*/strings*.xml` there, so expected values stay plain English.
  To test Arabic: `AppLocale.locale = Locale.forLanguageTag("ar-u-nu-latn")`, and set `Locale.ENGLISH` back in `@After`.

## Files and keys (one file per area, so parallel work never collides)
| Area | File (values/ and values-ar/) | Key prefix |
|---|---|---|
| home_calendar | strings_home_calendar.xml | `home_`, `cal_` |
| meeting_notes | strings_meeting_notes.xml | `meet_`, `note_` |
| settings_sheets | strings_settings_sheets.xml | `settings_`, `sheet_` |
| generated | strings_generated.xml | `gen_` |
| ai | strings_ai.xml | `ai_` |
| common | strings_common.xml (shared words: Cancel, Save, Done...) | `common_` |
| widget | strings_widget.xml (manifest and widget labels) | `widget_` |

Keys are snake_case `prefix_screen_thing`: `home_tab_brief`, `settings_language_title`, `gen_brief_next_meeting`. Use a
`common_` word when one fits, but edit only your own area's two files: a shared word that is missing goes into your file
with your prefix (and is named in your report). Add the English and the Arabic string in the same change.

## Rules
- Never build a sentence by joining pieces. One string with numbered arguments: `"%1$s at %2$s"`, `"%1$d of %2$d"`.
  The Arabic may reorder them. Arguments must match between the two languages (a test checks).
- Counts use `<plurals>`. Arabic needs zero, one, two, few, many and other; English one and other.
- Never translate proper names: Plait, Google, Google Meet, Microsoft Teams, Zoom, Webex, Outlook, iCloud, Gemini Nano,
  Whisper, Qwen, Markdown, ICS. Mark strings that must stay as written `translatable="false"`.
- User content (note text, invite text, meeting titles, names, emails) is never changed or translated. Show it with
  `style = PlaitType.body.userText()` so it keeps its own direction. Put it into a sentence through `Bidi.isolate(name)`.
- Digits are always Western 0-9 and the calendar Gregorian. Format dates, times and numbers with `AppLocale.locale`
  (`TimeFmt.fmt("EEE d MMM")`, `TimeFmt.clock(ms)`, `String.format(AppLocale.locale, ...)`), never `Locale.ENGLISH` or
  `Locale.getDefault()` for display text. Machine formats (ISO dates, file names, parsing) keep `Locale.ROOT`/`ENGLISH`.
- `.uppercase()` does nothing to Arabic; never rely on case for emphasis. Letter spacing is already 0 in Arabic (PlaitType).
- Add a translator comment `<!-- ... -->` above any string whose meaning is not obvious (a verb or a noun? a button or a title?).
- Arabic is natural, concise Modern Standard Arabic, gender-neutral where possible (nouns and passives rather than
  masculine imperatives: "يمكن اختيار" rather than "اختر"). Use Arabic punctuation (، ؛ ؟).
- Direction: use start/end (padding, Alignment, Arrangement), never left/right; `Icons.AutoMirrored.*` for any icon that
  points; `offset {}` mirrors by itself but touch x, `graphicsLayer.translationX`, `slideIn/OutHorizontally` and Canvas
  drawing do not: flip them with `AppLocale.isRtl` or `LocalLayoutDirection`.

## Completeness
Every English string has an Arabic one. Never add `tools:ignore="MissingTranslation"`: a string that must not be translated
is `translatable="false"`, anything else gets its Arabic twin. `I18nTest` fails on a missing or extra key or mismatched
arguments. Without Gradle, list the English keys missing from values-ar (PowerShell, from the repo root):

```powershell
$keys = { param($d) Get-ChildItem "app\src\main\res\$d\strings*.xml" | % { ([xml](Get-Content $_ -Raw -Encoding UTF8)).resources.SelectNodes('*') | ? { $_.translatable -ne 'false' } | % name } }
& $keys values | ? { $_ -notin (& $keys values-ar) }
```
